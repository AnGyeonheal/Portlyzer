# Portlyzer 구현 및 설계

## 목표와 범위

Portseido의 공개 기능을 벤치마크로 삼되 제품명, 화면 구성, 문구, 아이콘은 독자적으로 구성한다.
기본 언어는 한국어, 원장과 보고 통화는 KRW/USD다. 한국·미국 주식/ETF, 암호화폐,
사용자 정의 자산과 통화별 현금을 관리한다. 계좌 유형은 분류일 뿐 세법 판정이 아니다.
공개 문서에서 확인되지 않은 Portseido 동작은 기능 대응표에서 미확인으로 표시한다.

## 구조와 선택 근거

- Next.js App Router + React + TypeScript: UI/API를 한 서비스로 운영한다.
- Tailwind CSS + shadcn 스타일의 Radix 기반 UI 구성 요소 + Recharts: 접근성 및 반응형 UI.
- PostgreSQL + Prisma: 금액 Decimal, 외래키, 트랜잭션, 고유키로 원자성과 중복 방지.
- Better Auth: 비밀번호 해시/세션/인증 쿠키는 검증된 라이브러리가 담당한다.
- Nodemailer: SMTP/TLS 메일 발송. 요청별 전송 실패를 보존해 인증 라이브러리의 내부
  예외 처리로 실패가 성공 응답으로 바뀌지 않도록 한다. 복구 후 세션 폐기는 인증 계층에서 처리한다.
- Zod: 모든 쓰기 API와 가져오기 행을 서버에서 검증한다.
- Decimal.js 계산 모듈은 Next/DB와 독립적이며 API와 테스트가 같은 공개 인터페이스를 사용한다.
- 데이터 제공자는 HTTP 어댑터 경계 안에 두며 공개 환율 제공자, 선택적 주가 제공자,
  수동 입력, 명시적 데모를 구분한다. 장애 시 데모로 자동 대체하지 않는다.
- Vitest/Playwright: 수작업 기대값 단위 테스트와 실제 PostgreSQL/API/브라우저 검증.

## 데이터와 일관성

원본 거래, 현재 유효 거래, 수정 이력은 분리한다. 거래 삭제는 감사 이력을 유지하는 논리 삭제다.
사용자가 비밀번호를 재확인하고 명시적으로 계정 탈퇴를 확정한 경우에만 해당 사용자의 모든 데이터를 영구 삭제한다.
모든 사용자 데이터 읽기/쓰기는 인증된 사용자 ID를 소유권 조건에 포함한다.
거래 변경은 원장 유효성 검증, 현재 값, 수정 이력, 분개, 원장 버전 갱신을 한 트랜잭션으로
처리한다. 분석은 원장 전체 이력을 재생한 뒤 기간을 자르므로 과거 수정이 미래 분석에 반영된다.
필터는 기간/계좌/포트폴리오/통화가 함께 적용된다. 내부 이동은 선택 계좌 경계를 기준으로
통합 보기에서는 내부 거래, 개별 보기에서는 외부 현금 흐름으로 처리한다.
계좌가 없는 포트폴리오를 선택하면 빈 원장을 분석한다. 독립 엔진의 기본값인
"빈 계좌 목록 = 전체"를 UI의 명시적 빈 선택에 잘못 적용하지 않는다.

가져오기는 표준 XLSX 다운로드/작성 → 업로드/양식 확인·자동 열 연결 → 검증/수정 → 미리보기 → 확정이 기본이다.
기존 일반 CSV/XLSX는 사용자가 선택해 직접 열을 연결할 수 있다.
양식의 열/입력 안내/매핑/한도는 클라이언트와 생성기가 공유하며 예시 거래를 자동 포함하지 않는다.
고정 목록과 문자 수 검사를 제외한 수식은 차단하고, ExcelJS가 확장할 입력 검사 범위까지 로드 전에 제한한다.
파일 해시+행, 원본 거래 ID를 사용하며 같은 날짜/가격/수량이라는 이유로 거래를 삭제하지 않는다.
확정 전 데이터는 사용자 소유 가져오기 작업에 저장하고 확정은 원자적으로 실행한다.

## 구현 단계

1. 공개 기능 조사, 요구사항/계산 정책/설계/대응표
2. 인증, 스키마/마이그레이션, 계좌, 거래, 가져오기
3. 독립 계산 엔진, 제공자, 대시보드
4. 성과/배분/배당/거래/목표/설정
5. 실제 흐름 검증, 모바일, CI/Docker/운영 문서
6. 운영용 standalone 패키징, Windows 로컬 실행 제어, 암호화 백업/새 DB 복원, 메일 인증/복구 검증

구현 상태와 실제 실행 결과는 [DELIVERY.md](DELIVERY.md)에 기록한다.
운영 공개 배포, 유료 서비스 가입, 비밀키 발급, 실제 사용자 데이터 삭제는 수행하지 않는다.
