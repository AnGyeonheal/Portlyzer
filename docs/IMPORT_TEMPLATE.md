# 거래내역 엑셀 양식

## 기본 사용 순서

1. 로그인 후 **거래 내역 → 파일 가져오기 → 표준 엑셀 양식**을 선택한다. 기본 선택값이다.
2. **엑셀 양식 다운로드**로 `portlyzer-transactions-v1.xlsx`를 받는다.
3. `거래내역` 시트의 2행부터 실제 거래를 연속해서 작성한다. 양식에는 예시 거래가 없다.
4. 웹 화면에서 **가져올 계좌**를 정확히 선택한 뒤 파일을 올린다. 파일 하나는 한 출발 계좌에 반영된다.
5. **엑셀 업로드·검증**을 누르면 열 이름과 순서를 확인하고 자동 연결·행 검증을 수행한다.
6. 오류를 수정하고 필요한 중복 처리 결정을 선택한 뒤 **다시 검증 → 최종 미리보기 → 가져오기 확정**을 진행한다.

업로드와 검증만으로 거래가 저장되지는 않는다. 확정 시 전체 후보 원장을 재검증하고 한 번에 반영한다.
원본 행 값, 열 연결, 수정 이력과 파일 식별 정보는 보존한다. 원본 엑셀 파일 자체도 별도로 보관한다.

## 열 순서와 입력값

열을 지우거나 이름·순서를 바꾸지 않는다. 사용하지 않는 열은 빈칸으로 남긴다.

| 순서 | 열 | 작성 방법 |
| --- | --- | --- |
| A | 거래일 | 모든 행 필수. `YYYY-MM-DD` 권장. 같은 날은 위에서 아래 순서 |
| B | 거래 유형 | 모든 행 필수. 목록의 매수/매도/입금/출금/배당/이자/수수료/세금/환전/이체/분할/평가 |
| C | 통화 | 모든 행 필수. 실제 거래 통화 `KRW` 또는 `USD` |
| D | 종목 코드 | 종목 거래에 필요. `005930`처럼 앞자리 0 유지 |
| E | 거래소 | 종목 거래에 필요. 예: `KRX`, `NASDAQ`, `NYSE` |
| F | 수량 | 매수·매도·증권 이체 수량 |
| G | 단가 | 체결 단가 또는 CUSTOM 자산의 단위당 평가액 |
| H | 금액 | 입출금·배당·이자·독립 수수료/세금·현금 이체·환전 출금 총액 |
| I | 수수료 | 거래 수수료. 빈칸은 0 |
| J | 세금 | 거래 세금/원천징수액. 빈칸은 0 |
| K | 메모 | 선택. 최대 1,000자 |
| L | 태그 | 선택. 쉼표 구분, 태그당 40자·최대 20개 |
| M | 원본 거래 ID | 선택. 거래별 고유 값. 재업로드 중복 확인에 권장 |
| N | 받는 계좌 ID | 이체에 필요. 업로드 화면의 **이체용 계좌 ID**에서 확인 |
| O | 도착 통화 | 환전의 입금 통화. 출금 통화와 달라야 함 |
| P | 환전 입금액 | 실제 입금된 도착 통화 금액 |
| Q | 분할 비율 | 분할·병합에 필요. 1주→2주는 `2`, 2주→1주는 `0.5` |

초록색 열은 모든 행에 필요한 세 열이다. 나머지는 거래 유형에 따라 필요하다.
셀을 선택하면 입력 안내가 표시되며 거래 유형과 통화에는 고정 목록이 있다.
거래 유형에 따른 필수값, 잔고/수량, 중복은 서버에서 다시 검증한다.

### 자주 쓰는 거래

- **매수·매도:** 종목 코드·거래소·수량·단가를 입력하고 금액은 비운다. 수수료·세금은 별도 열에 적는다.
- **입금·출금·이자:** 금액을 입력한다.
- **배당:** 종목 코드·거래소·세전 금액을 입력한다. 원천징수는 세금 열에 적는다.
- **수수료·세금 자체를 한 거래로 기록:** 해당 비용을 금액에 적고 같은 이름의 비용 열은 비운다.
- **현금 이체:** 금액과 받는 계좌 ID. **증권 이체:** 종목 코드·거래소·수량과 받는 계좌 ID.
- **환전:** 통화/금액은 출금 쪽, 도착 통화/환전 입금액은 입금 쪽이다. 같은 계좌 안의 환전이다.
- **평가:** 미리 등록한 CUSTOM 자산의 단위당 가격을 입력한다. 명시적인 0도 허용한다.

예를 들어 **가정상** 10주를 단가 180 USD에 샀고 수수료가 1 USD라면,
매수 행의 수량=10, 단가=180, 수수료=1, 금액=빈칸이다. 현금은 1,801 USD 감소한다.
그 전에 실제 입금·취득 이력이 있어야 하며 부족한 잔고를 자동으로 만들지 않는다.

## 서식과 안전 제한

- `.xlsx`, 최대 **2 MiB·2,000건**, 단일 시트. 준비된 입력 범위는 2~2001행이다.
- 입력 셀은 텍스트 형식이다. 숫자를 15자리에서 반올림하거나 종목 코드 앞자리 0을 잃지 않도록
  이 형식을 유지한다. 원본에서 이미 손실된 자리수나 0은 자동 복원하지 않는다.
- 숫자는 소수점 `.`을 쓰며 최대 소수 12자리 등 서버의 금융 정밀도 제한을 따른다.
  계산식 대신 값을 입력한다. 거래일의 미래 여부는 UTC 날짜 기준으로 검사한다.
- 마지막 거래 뒤의 서식만 있는 빈 행은 무시한다. 중간 빈 행은 오류로 표시되므로 파일에서
  지우거나 검증 화면에서 제외한다. 원본 Excel 행 번호가 바뀌지 않도록 중간 행을 몰래 압축하지 않는다.
- 셀 수식, 정의된 이름/참조 범위, 매크로, 병합·숨김, 추가 시트, 외부 연결/임베디드 개체는 허용하지 않는다.
  양식에 포함된 고정 목록과 상수 글자 수 검사만 허용하며 검사 대상 범위도 서버에서 제한한다.
- 새 종목은 기본적으로 STOCK으로 생성된다. ETF·암호화폐·CUSTOM은 같은 코드/거래소/통화로
  먼저 종목을 등록한다. 거래 입력은 시세·환율 등록과 별개이며 없는 가격을 0으로 평가하지 않는다.
- 같은 파일은 중복 확정하지 않는다. 변경된 파일의 유사 거래는 반영/제외를 직접 판단한다.
  서로 다른 거래에 같은 원본 거래 ID를 재사용하지 않는다.

## 다른 입력 방식

**일반 CSV·XLSX**를 선택하면 기존처럼 직접 열을 연결할 수 있다.
CSV는 UTF-8이며 일반 파일도 2 MiB·2,000행·40열 및 XLSX 안전 제한을 따른다.
`.xls`, `.xlsm` 및 아직 검증하지 않은 증권사별 전용 파일 형식을 지원한다고 표시하지 않는다.
한 건씩 입력할 때는 기존 **거래 추가**를 사용한다.

API는 인증된 `GET /api/imports/template`으로 빈 XLSX를 내려준다.
표준 업로드는 multipart의 `file`, `accountId`, `templateId=portlyzer-transactions-v1`을 사용한다.
일반 업로드는 `templateId`를 보내지 않으며 기존 검증/확정 API와 원장 보호 규칙을 공유한다.
